## 1. 项目概述

### 1.1 一句话定义

AI Avatar Twin 是一款面向 AI 行业内容创作者的「选题发现 → 脚本生成 → 数字人口播视频制作 → 发布素材包导出」工作台。用户可以选择模板形象，或上传本人照片生成 3D 渲染风的虚拟数字人形象，配置声音和表达风格后，系统自动追踪 AI 行业前沿信息，筛选选题，生成口播稿，制作成数字人口播短视频，用户审核后导出发布素材包；抖音平台的授权发布在后续版本接入。

### 1.2 产品定位

AI Avatar Twin 不是单纯的数字人生成器，也不是泛社交媒体 Agent，而是一个垂直聚焦 AI 行业内容的「选题发现 + 脚本生成 + 数字人视频制作 + 发布复盘」工作台。

产品核心价值是帮助创作者把高频、碎片化、更新极快的 AI 行业信息，稳定转化为有个人风格、有事实依据、可持续发布的短视频内容。

产品形态（V1）：Web 端（浏览器访问），不做 App / 移动端 / 小程序。

### 1.3 核心闭环（标注 V1 边界）

```text
【V1 范围】
配置数字人形象与表达风格
→ 接入 AI 行业信息源
→ 自动抓取前沿信息
→ 选题筛选和来源标注
→ 生成短视频口播稿
→ 按数字人风格改写
→ 生成数字人口播视频
→ 用户审核和修改
→ 导出发布素材包
→ 用户手动发布 + 人工录入播放数据（可选）

【V1.1 / V2 范围】
→ 授权发布到目标平台
→ 自动回收播放和互动数据
→ 反向优化下一期选题和脚本
```

### 1.4 事实核查与边界修正

根据公开平台能力：抖音开放平台存在「在用户授权情况下代替用户发布内容到抖音」的能力，但通常需要开发者账号、应用审核、scope 权限、用户授权、媒体上传流程和平台合规审核。

因此 **V1 不把「全自动跨平台发布」作为必交付主线**。V1 优先保证内容生产闭环：选题、脚本、数字人视频、字幕、封面、标题、标签和发布素材包。平台授权发布放入 V1.1 或 V2。

**数字人实现选型（V1 已决策）**：V1 数字人提供两种形象来源——**模板形象（兜底体验）+ 用户本人照片生成的 3D 渲染风虚拟形象（贴合本人）**。生成链路为「用户照片 → 图生图生成 3D 渲染风形象 → 形象口型驱动 + 默认 TTS 音色 + 视频合成渲染」；不自研数字人模型、不做实时互动直播、不默认提供声音克隆（声音克隆列入 V1.1）。

**语言与平台（V1 已决策）**：V1 语言暂定中文、播放平台暂定抖音；英文/双语及其他平台（TikTok、X、小红书）在后续版本评估。

参考资料：

- 抖音开放平台：代替用户发布内容到抖音 [developer.open-douyin.com](https://developer.open-douyin.com/)

## 2. 目标与非目标

### 2.1 产品目标

1. 帮助 AI 行业内容创作者稳定发现值得讲的 AI 前沿选题。
2. 将公开信息自动整理为可核查、可追溯的短视频口播脚本。
3. 将用户的数字人形象、声音、表达风格沉淀为固定 IP。
4. 降低真人出镜、写稿、剪辑、字幕、封面和发布准备成本。
5. 通过播放、互动、完播、评论等数据反向优化后续选题和脚本（V1.1 起）。

### 2.2 V1 成功标准

1. 用户选择模板形象或上传本人照片完成数字人配置后，**单条视频从选题确认到素材包导出 ≤ 30 分钟**（不含数字人形象首次生成耗时）。
2. 单条视频从选题确认到成片导出的人工操作步骤不超过 5 步。
3. 每条脚本至少包含 2 个可追溯信息来源（仅 1 个来源时显式标记「单一来源」）。
4. 用户可以在发布前审核和修改事实点、脚本、标题、封面和字幕。
5. 系统可以记录每条内容的选题、来源、脚本版本、视频版本和发布结果。

### 2.3 非目标

V1 不做以下内容：

1. 不承诺全自动发布到任何平台。
2. 不做无审核的自动搬运或自动洗稿。
3. 不做复杂视频剪辑工作站。
4. 不做多人协作和机构级账号矩阵。
5. 不做实时互动数字人直播。
6. 不默认克隆用户声音，除非用户明确授权并完成合规确认（V1.1）。
7. 不允许上传可识别的真实他人形象或声音生成数字人（仅限用户本人形象、系统模板形象、已购版权素材）。
8. 不做 App / 移动端 / 小程序（V1 为 Web 端，浏览器访问）。

## 3. 核心用户

### 3.1 主要用户

AI 行业短视频内容创作者：

- 想做 AI 行业短视频账号，但没有稳定时间选题、写稿、剪辑的人。
- 希望持续输出 AI 前沿资讯、工具更新、论文解读、产品观察的人。
- 想打造个人 IP，但不想每次真人出镜的人。

### 3.2 次要用户

产品经理、独立开发者、AI 学习者：

- 希望用数字人方式沉淀自己的观点、学习成果和项目观察。
- 希望把每天看到的 AI 信息转化为可复用内容资产。
- 希望用低成本方式验证自己的 AI 内容账号定位。

### 3.3 用户画像

#### 用户 A：AI 工具分享博主

每天关注大量 AI 工具更新，但没有时间写脚本和剪视频。TA 需要系统从官方博客、GitHub、产品更新、X 热帖中发现选题，并自动生成「这是什么、有什么用、适合谁、怎么用」的短视频脚本。

#### 用户 B：产品经理 / 独立开发者

TA 经常研究新 AI 产品，希望用账号沉淀观点。TA 更需要系统帮助做信息核查、观点提炼和口播表达，而不只是生成新闻摘要。

#### 用户 C：不想真人出镜的个人 IP 创作者

TA 有明确表达风格，但真人出镜成本高。TA 需要固定的数字人形象、声音和口头禅，让账号长期保持稳定人设。

## 4. 用户痛点

1. AI 行业信息更新快，用户很难持续追踪最前沿动态。
2. 抓到信息后，不知道哪些值得讲、哪些适合做短视频。
3. 从资料到口播稿、标题、封面、视频剪辑和发布，链路很长。
4. 真人出镜成本高，需要稳定状态、场景、设备和时间。
5. 内容风格容易不统一，账号难以形成清晰人设。
6. 多平台发布需要适配不同比例、标题、标签、授权和审核规则。
7. 内容做完后缺少复盘，下一次选题仍然依赖个人感觉。

## 5. 产品差异点

1. 不是单纯数字人生成器，而是从 AI 行业信息发现到数字人内容发布准备的完整链路。
2. 不是通用社交媒体 Agent，而是聚焦 AI 行业前沿内容，选题更垂直。
3. 不是只生成脚本，而是沉淀固定人设的数字人 IP。
4. 不是全自动搬运信息，而是加入来源标注、观点生成和用户审核。
5. 不是只发布一条内容，而是持续学习哪些选题和表达更适合用户账号。
6. 第一版不强行做全自动发平台，而是先保证内容生产闭环可控。

## 6. 使用流程

### 6.1 首次配置流程

1. 用户注册 / 登录。
2. 创建项目（Project）。
3. 创建数字人 Profile：默认使用模板形象，可立即开始体验（低门槛）。
4. （可选）系统引导上传本人照片，生成 3D 渲染风虚拟数字人形象；可跳过，之后随时补传。
5. 配置声音：默认 TTS 音色（V1）；授权声音 / 第三方 TTS（V1.1）。
6. 配置表达风格：专业、犀利、亲切、科技感、教学型等。
7. 配置内容方向：AI 工具、AI 产品、AI 编程、AI 论文、AI 创业、综合资讯。
8. 配置信息源：官方博客、RSS、产品更新页、手动 URL。
9. 确认语言（暂定中文）与目标平台（暂定抖音）。
10. 生成并保存数字人 Profile。

### 6.2 日常生产流程（V1）

1. 系统按计划抓取 AI 行业信息。
2. 系统生成候选选题列表（含冷启动策略，见 7.3）。
3. 用户选择一个选题，或让系统推荐一个选题。
4. 系统展示选题依据、来源链接、事实摘要和风险提示。
5. 用户确认选题。
6. 系统生成短视频脚本（含来源引用与风险标注）。
7. 系统按数字人风格改写脚本（含目标语言）。
8. 用户编辑脚本、标题、封面文案、字幕样式。
9. 系统生成数字人口播视频。
10. 用户预览并修改（支持版本回退）。
11. 导出素材包，用户手动发布。
12. （V1 可选）用户手动录入播放数据，形成基础复盘。

> V1.1 起：接入平台授权发布、自动回收数据、复盘建议闭环。

## 7. 功能需求

### 7.0 用户与账户（新增，P0）

用户可以注册登录并创建项目，不同用户数据相互隔离。

- 注册 / 登录：手机号或邮箱 + 验证码，或第三方登录（微信 / Google 等，按目标市场）。
- 项目（Project）管理：创建、重命名、归档、删除；一个项目绑定至少一个数字人 Profile。
- 数据隔离：用户 A 看不到用户 B 的信息源、选题、脚本、视频与发布记录。

验收标准：

- 用户可以完成注册、登录、退出。
- 用户可以创建并切换多个项目。
- 用户数据按 user_id 隔离，接口层与存储层双重校验。

### 7.1 数字人 Profile 配置

优先级：基础 P0 / 高级 P1

用户可以创建一个代表自己账号风格的数字人 Profile。

形象选择逻辑（V1）：

- 默认使用**模板形象**，用户无需准备素材即可快速体验。
- 系统在创建 Profile 后引导用户**上传本人照片**，系统将照片生成 **3D 渲染风虚拟形象**（皮克斯质感、保留面部特征），再由该形象口播（可选，可跳过，随时补传）。
- 模板形象与本人照片生成的 3D 形象共用同一套口型驱动管线。

核心字段：

| 字段 | 说明 | V1 能力 |
|-|-|-|
| 数字人名称 | 账号人设名称 | P0 |
| 形象素材 | 模板形象（默认兜底）；用户上传本人照片，生成 3D 渲染风虚拟形象（贴合本人） | P0 |
| 声音类型 | 默认 TTS（V1）；授权克隆声音、第三方声音（V1.1） | P0 默认 TTS / P1 其他 |
| 表达风格 | 专业、轻松、犀利、教学、评论、资讯 | P0 |
| 语言 | 中文（暂定） | P0 |
| 口头禅 | 可选，用于强化人设 | P0 |
| 禁用表达 | 不希望出现的词、语气或立场 | P0 |
| 内容领域 | AI 工具、AI 产品、论文、创业、编程等 | P0 |
| 平台偏好 | 抖音（暂定） | P0 |
| 视频比例 | 9:16、1:1、16:9 | P0 |

验收标准：

- 用户可以新增、编辑、删除 Profile。
- 用户可以保存至少 1 个默认 Profile。
- 脚本生成时必须读取 Profile 风格、语言、内容方向配置。
- 视频生成时必须读取形象、声音、比例和字幕样式配置。

### 7.2 信息源管理

优先级：RSS / 手动 URL / 网页 URL 为 P0；GitHub / X 为 P1

用户可以配置 AI 行业信息源，系统按计划抓取内容并结构化。

信息源类型：

| 类型 | 示例 | V1 支持方式 |
|-|-|-|
| RSS | OpenAI Blog、Anthropic News、Google DeepMind Blog | P0 |
| 网页 URL | 产品更新页、官方公告页 | P0 |
| 手动输入 | 用户粘贴链接或文本 | P0 |
| GitHub Repo | AI 工具仓库、开源项目 | P1 |
| X 账号 / 列表 | AI 公司、研究员、创作者 | P1 |

抓取字段：

| 字段 | 说明 |
|-|-|
| 标题 | 原始标题 |
| 来源 | 站点、账号或仓库 |
| 原始链接 | 可追溯 URL |
| 发布时间 | 原文发布时间 |
| 抓取时间 | 系统采集时间 |
| 摘要 | LLM 生成摘要 |
| 关键词 | AI 模型、产品、技术、公司等 |
| 可信度 | 来源类型、是否官方、交叉验证来源数 |
| 适合视频化评分 | 0-100 |

验收标准：

- 用户可以新增、禁用、删除信息源。
- 系统可以展示抓取状态：成功、失败、待重试。
- 每条内容必须保留原始链接。
- 同一链接不重复入库。
- 抓取计划：每日 2 次（默认 08:00 / 20:00，可配置），失败重试 3 次后置为「待重试」。

### 7.3 选题筛选

优先级：P0

系统根据抓取信息生成候选短视频选题。

选题评分维度（规则初筛 + LLM 打分，0-100）：

| 维度 | 说明 |
|-|-|
| 新鲜度 | 是否为近期更新 |
| 重要性 | 是否来自重要公司、产品或论文 |
| 受众相关性 | 是否符合用户账号方向（冷启动期以内容方向配置替代） |
| 视频化潜力 | 是否容易讲清楚、制造开头钩子 |
| 观点空间 | 是否能产生用户自己的判断 |
| 风险程度 | 是否涉及未经证实、争议或夸大表述（反向扣分） |

选题卡片内容：

- 标题建议
- 一句话看点
- 推荐理由
- 关键事实
- 主要来源
- 适合平台
- 风险提示
- 推荐视频角度

冷启动策略：

- 新用户无历史数据时，「受众相关性」使用首次配置的内容方向作为种子。
- 系统为新用户生成首批「种子选题」（来自默认预置信息源或手动 URL）。
- 前 10 条选题由用户人工校准（收藏 / 忽略），用于后续个性化。

验收标准：

- 系统每天至少生成一批候选选题（默认 10～20 条）。
- 用户可以按领域、来源、热度、发布时间筛选。
- 用户可以收藏、忽略、标记不感兴趣。
- 被忽略的选题类型会影响后续推荐。
- 综合评分 ≥ 70 视为「推荐」，可配置阈值。

### 7.4 事实核查（来源标注与风险提示）

优先级：P0

系统在生成脚本前对关键事实进行**来源标注与风险提示**（V1 基于已接入信息源，不承诺通用联网搜索）。

规则：

1. 优先引用官方来源。
2. 每条脚本至少保留 2 个来源，若只有 1 个来源需标记「单一来源」。
3. 对模型能力、价格、发布时间、融资金额、benchmark 等高风险信息进行显式标注。
4. 不确定内容不得写成确定事实。
5. 不使用「全球第一」「最强」「颠覆行业」等无法证明的绝对化表达，除非来源明确且上下文完整。
6. 多信息源交叉比对：同一事实有 ≥ 2 个独立来源时标注「多源交叉验证」；仅 1 个来源标注「单一来源」。

> V1.1 增强：接入联网搜索 API 做外部交叉验证。

验收标准：

- 脚本页必须展示事实来源列表。
- 高风险事实必须显示风险标签。
- 用户可以手动删除或替换来源。
- 用户修改关键事实后，系统需重新生成相关脚本文案。

### 7.5 口播脚本生成

优先级：P0

系统根据选题和数字人 Profile 生成短视频口播脚本。

脚本结构：

| 模块 | 说明 |
|-|-|
| 开头钩子 | 3-5 秒内说明为什么值得看 |
| 背景说明 | 交代事件、产品或技术背景 |
| 核心事实 | 讲清楚发生了什么 |
| 观点解释 | 为什么重要，对谁有影响 |
| 使用建议 | 对创作者、PM、开发者或学习者的建议 |
| 结尾引导 | 评论、收藏、关注或下一期预告 |

脚本参数：

| 参数 | 说明 |
|-|-|
| 视频时长 | 30 秒、60 秒、90 秒、3 分钟 |
| 语气 | 专业、轻松、锐评、教学 |
| 平台 | 抖音（暂定） |
| 语言 | 中文（暂定） |
| 信息密度 | 低、中、高 |
| 受众 | 入门用户、AI 从业者、产品经理、开发者 |

验收标准：

- 用户可以一键生成脚本。
- 用户可以选择不同风格重新生成（V1.1 起支持不同语言）。
- 脚本必须附带来源引用与风险标注。
- 脚本不得包含未标注的事实。
- 脚本可以导出为 Markdown 或纯文本。

### 7.6 数字人口播视频生成

优先级：P0

系统将脚本转化为数字人口播视频。

**V1 生成方案（已决策）**：用户上传本人照片 → 图生图生成 3D 渲染风虚拟形象（皮克斯质感、保留面部特征）→ 形象口型驱动 + 默认 TTS 音色 + 视频合成渲染（字幕、封面、标题条），输出 MP4。模板形象为兜底，跳过照片上传直接用预置形象。

视频组成：

| 组成 | 说明 |
|-|-|
| 数字人口播画面 | 3D 渲染风虚拟形象（由本人照片生成，或模板形象兜底） |
| 口播音频 | 默认 TTS（V1）；授权声音（V1.1） |
| 字幕 | 自动对齐脚本和音频 |
| 标题条 | 视频开头标题 |
| 信息卡片 | 关键数据、产品名、观点总结 |
| 背景 | 简洁科技风背景或用户上传背景 |
| 封面 | 标题、人物、关键词 |

V1 视频能力：

- 9:16 竖屏视频（可扩展 1:1、16:9）。
- 支持 30 秒、60 秒、90 秒。
- 支持自动字幕（SRT）。
- 支持封面图导出。
- 支持 MP4 导出。
- 支持重新生成音频、字幕和封面。
- 语言：中文（暂定）。

验收标准：

- 用户确认脚本后可以生成视频。
- 视频生成失败时显示原因并可重试。
- 用户可以预览视频。
- 用户可以下载 MP4、封面图、标题、简介、标签。
- 视频生成采用异步任务，提供队列状态（排队中 / 生成中 / 成功 / 失败）。

### 7.7 用户审核与修改

优先级：P0

所有内容发布前必须经过用户确认。

审核项：

- 选题
- 来源
- 脚本
- 数字人声音
- 字幕
- 标题
- 封面
- 平台文案
- 风险提示

验收标准：

- 未经用户确认不得进入发布或导出步骤。
- 每次修改生成一个版本记录（脚本、视频均有版本）。
- 用户可以回退到上一个脚本版本或上一个视频版本。

### 7.8 发布素材包

优先级：P0

V1 输出发布素材包，方便用户手动发布。

素材包包括：

- MP4 视频
- 封面图
- 平台标题
- 简介文案
- 标签 / 话题

- 口播脚本
- 字幕文件 SRT

平台适配：

| 平台 | V1 能力 | 后续能力 |

| TikTok / X / 小红书 | V1 暂不支持 | 后续版本评估发布接口 |

验收标准：

- 用户可以选择目标平台并生成对应素材。
- 素材包内容可以一次性下载。
- 不同平台文案长度和标签格式需区分。

### 7.9 数据复盘

优先级：P1

V1 可先支持用户手动录入：

- 播放量
- 点赞

- 哪些视频评论更多

验收标准：

- 用户可以为每条内容录入数据。
- 系统可以按平台和时间展示基础趋势。
- 系统可以基于历史表现调整选题推荐。

## 11. 合规与风控

### 11.1 内容合规

1. 脚本必须基于来源生成，不允许凭空捏造行业新闻。
2. 对推测性观点必须标注为「推测」或「个人判断」。
3. 不允许生成诽谤、侵权、煽动、违法内容。
4. 不允许未经授权搬运他人视频素材。
5. 平台发布文案需避免违规营销词和绝对化宣传。

### 11.2 声音与肖像授权

1. 用户上传**本人**形象或声音时，需要完成本人身份确认并声明拥有使用权。
2. **V1 禁止上传可识别的真实他人形象或声音**（含名人/公众人物）用于生成数字人；仅允许用户本人形象、系统模板形象、已购版权素材。
3. 声音克隆能力默认关闭，V1 不提供；V1.1 开启前必须完成授权确认与审计记录。
4. 所有生成视频应保留项目记录，以便追溯来源和授权。
5. 用户上传素材即授权系统在本产品范围内使用，明确展示授权条款。

### 11.3 平台发布风险

1. 抖音 API 权限、审核和 scope 可能变化，不应在 V1 承诺稳定自动发布。
2. V1 使用人工发布素材包更稳妥。

## 15. 验收标准

### 15.1 端到端验收

给定一个 AI 行业新闻链接，用户可以完成：

1. 导入链接。
2. 系统提取正文并生成摘要。
3. 系统生成 3 个候选选题。
4. 用户选择一个选题。
5. 系统展示来源和风险提示。
6. 系统生成 60 秒口播脚本（含来源引用）。
7. 用户编辑脚本并确认。
8. 系统生成 9:16 数字人口播视频（模板形象/本人照片 + 默认 TTS）。
9. 用户下载素材包。

### 15.2 质量验收

1. 脚本必须包含来源引用。
2. 不确定事实不得以确定语气表达。
3. 视频字幕与口播基本同步。
4. 导出素材包完整可用。
5. 视频生成失败时有明确错误提示。
6. 用户可以重新生成脚本或视频。

### 15.3 体验验收

1. 首次配置流程不超过 10 分钟（数字人形象首次生成异步进行，不计入配置时长）。
2. 从选题确认到视频导出不超过 30 分钟（不含异步排队等待）。
3. 核心操作路径清晰：选题、脚本、视频、导出。
4. 用户始终能看到当前内容使用了哪些来源。

## 16. 风险与应对

| 风险 | 影响 | 应对 |
|-|-|-|
| 信息抓取失败 | 无法生成选题 | 支持手动 URL 和 RSS 兜底；重试 3 次 |
| 脚本事实错误 | 损害账号可信度 | 来源引用、风险标签、多源交叉比对、用户审核 |
| 视频生成慢 | 影响体验 | 异步任务、队列状态、失败重试、并发上限 |
| 视频生成成本过高 | 成本失控 | 单条成本预算护栏、复用渲染管线、形象生成成本单列 |
| 平台发布接口不稳定 | 发布链路受阻 | V1 先导出素材包 |
| 声音 / 肖像侵权 | 法务风险 | V1 禁止真实他人形象/声音、授权确认、审计记录、声音克隆默认关闭 |
| 内容同质化 | 账号缺少差异 | Profile 风格、观点生成、历史复盘 |

## 17. 非功能需求（新增）

### 17.1 性能与时延

- 单条 60 秒视频生成：目标 ≤ 10 分钟（P95 ≤ 15 分钟），异步执行。
- 脚本生成：目标 ≤ 30 秒。
- 信息抓取：每日 2 次，单次全量抓取 ≤ 30 分钟。
- 页面基础接口响应：P95 ≤ 1 秒（不含生成类异步任务）。
- 浏览器兼容：Chrome / Edge / Safari 最近两个大版本；桌面优先，手机浏览器可访问。

### 17.2 并发与容量

- 单用户最多 2 条视频并行渲染。
- 系统级渲染队列，按优先级与提交时间排队。
- 支持水平扩展渲染 worker。

### 17.3 成本预算

- 单条视频生成成本（TTS + 渲染 + 模型调用）目标：≤ 3 元（待 TTS / 渲染供应商报价后锁定）。
- 模型调用设费用护栏（单用户单日调用次数上限）。

### 17.4 可用性与容错

- 视频生成失败自动重试 1 次，仍失败则明确报错。
- 信息抓取失败进入重试队列，不影响其他流程。
- 数据定期备份，故障可恢复。

### 17.5 安全

- 密钥外置（.env / 密钥管理服务），不落库明文。
- 用户数据隔离（user_id 双重校验）。
- 上传素材进行内容安全与版权风险扫描。

### 17.6 可观测性

- 日志：每次抓取、生成、渲染的耗时与结果。
- 指标：生成成功率、平均时延、失败率、成本。
- 轨迹：记录选题 → 脚本 → 视频 → 发布的完整链路。

## 18. 已决策项与待确认项

### 18.1 已决策（本优化版明确）

1. V1 数字人 = 模板形象（兜底）+ 用户本人照片（贴合本人）两种；均走照片驱动 + 默认 TTS + 视频合成，不自研、不实时直播、不做声音克隆。
2. V1 语言 = 暂定中文；V1 平台 = 暂定抖音。
3. V1 声音 = 默认 TTS；声音克隆后移到 V1.1。
4. V1 事实核查 = 来源标注 + 风险提示 + 多源交叉比对，不承诺联网搜索。
5. 允许标注「AI 生成 / 数字人出镜」（V1 在导出素材包文案中默认提供该标注选项）。
6. 数字人形象生成选型 = 照片驱动（EchoMimic）+ 国内云 TTS + 视频合成；落地路径为先第三方 API 验证、后自建降本（详见《数字人形象生成-选型评估.md》）。
7. 产品形态 = Web 端（浏览器访问），V1 不做 App / 移动端 / 小程序。

### 18.2 待产品确认（不影响 P0 开工）

1. 默认 TTS 供应商与音色清单（待商务报价锁定）。
2. 单条视频生成成本预算目标（17.3 暂定 ≤ 3 元，待确认）。
