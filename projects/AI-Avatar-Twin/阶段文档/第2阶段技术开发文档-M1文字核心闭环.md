# 第 2 阶段技术开发文档｜M1 文字核心闭环

> 配套文档：PRD V1.2（rev53）、《技术适配声明》、AI Agent 产品 Vibe Coding 通用技术栈手册。
> 本文档只覆盖 M1（阶段 2 第 1 子阶段）。不提前实现账户、视频、正式前端。

## 一、阶段目标
- 交付范围（对齐 PRD 7.2 手动 URL / 7.3 选题 / 7.4 事实核查 / 7.5 脚本 / 7.7 版本）：**手动贴链接 → 提取正文 → 生成摘要 → 生成 3 个候选选题（评分/风险/来源）→ 选 1 个 → 生成 60 秒口播脚本（含来源引用与风险标注）→ 编辑/版本/回退 → 导出 Markdown/纯文本**。
- 阶段产物：FastAPI 后端 + SQLite 持久化 + 单个 HTML 最小验收界面 + mock 测试 + 真实冒烟记录。
- 验收标准（对齐 PRD 2.2/7.5/15.2）：
  1. 贴任意 AI 行业网页 URL，能提取正文并生成结构化摘要（标题/摘要/关键词/可信度/视频化潜力）。
  2. 一次生成 3 个候选选题，每个含：标题、视频角度、一句话看点、关键事实、主要来源、风险提示、评分与分维度分值。
  3. 生成脚本附带来源引用与风险标注；不确定事实不以确定语气表达；脚本可导出 Markdown 和纯文本。
  4. 每次修改生成版本记录，可回退到上一个版本。
  5. 生成效果"好不好"由真实样例打分定标（D2/D3，本阶段真实冒烟时进行）。
- 明确不做：用户账户/登录（M2）、数字人 Profile（M2）、RSS/定时抓取（M2/暂缓）、TTS/数字人渲染/视频/素材包 ZIP（M3）、正式前端（M4）、抖音授权发布（V1 不做）。
- 本阶段主链路片段：`URL → SourceItem(摘要) → Topic×3 → 选 Topic → Script → 版本/导出`。

## 二、技术适配摘要
- 引用《技术适配声明》结论：纵向切片（路径 B）。
- 本阶段采用：Python + FastAPI + Pydantic + pytest；SQLite + SQLAlchemy；文字模型阿里云百炼 DashScope（qwen-plus，OpenAI 兼容）。
- 本阶段启用：SQLite+SQLAlchemy（多实体）、SSE（脚本流式）、本地文件目录（导出产物）；信息抓取（手动 URL 解析）。
- 本阶段偏离/暂缓：网页抓取暂用 httpx+BeautifulSoup 轻量清洗（不用 Crawl4AI，M2 评估）；Alembic 暂缓用 create_all；真实短信/定时抓取/视频/抖音发布均不在 M1。

## 三、技术栈与模型
- 后端：Python 3.13（本机）/ 目标 3.12（上线前跑通）、FastAPI、Pydantic v2、SQLAlchemy、httpx、beautifulsoup4、python-dotenv、pytest、pytest-asyncio。
- 模型：`MODEL_NAME=qwen-plus`、`MODEL_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1`、超时 60s、最多重试 2 次（含 SDK/客户端初始化失败的兜底）。
- 三份 Prompt 契约（摘要 / 选题 / 脚本）均走"模型输出 JSON + 后端宽容解析 + Pydantic 强校验"。

## 六、数据、资产与状态
- 持久化：SQLite（`backend/data/avatar_twin.db`），SQLAlchemy 建模；导出文件存 `backend/data/exports/`，元数据入 Script 表。
- 表（字段对齐 PRD 9.2/9.3/9.4 的 M1 子集）：
  - `source_items`：id、source_type、source_name、original_url、title、content_text、published_at、fetched_at、summary、keywords(JSON)、is_official、cross_check_count、credibility_score、video_potential_score、status。
  - `topics`：id、source_item_id、title、angle、summary、key_facts(JSON)、source_urls(JSON)、score、score_breakdown(JSON)、risk_level、risk_flags(JSON)、status、created_at。
  - `scripts`：id、topic_id、duration_target、platform、language、content、fact_claims(JSON)、risk_flags(JSON)、source_urls(JSON)、version、status、created_at、updated_at。
  - `script_versions`：id、script_id、version、content、fact_claims(JSON)、risk_flags(JSON)、source_urls(JSON)、created_at。
- 状态机（M1）：
  - SourceItem：`fetched → summarized → failed`（failed 可重试）。
  - Topic：`new → selected → scripted`（selected 表示用户已选，scripted 表示已生成脚本）。
  - Script：`draft → approved`（回退仅回到历史 version 内容，状态不变）。
- 资产清理：导出文件按需生成；删除脚本不删导出文件（MVP 本地，生产再定回收）。

## 七、API / 工具设计
统一错误结构 `{"error": {"code", "message"}}`；所有接口校验请求体。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/sources` | body `{url}`；抓取并保存（不调模型），返回 SourceItem |
| POST | `/api/v1/sources/{id}/summarize` | 生成摘要（调模型），返回 SourceItem |
| GET | `/api/v1/sources` | 列表 |
| GET | `/api/v1/sources/{id}` | 详情 |
| POST | `/api/v1/sources/{id}/topics` | 生成 3 个候选选题，返回 Topic[] |
| GET | `/api/v1/topics` | 列表（可按 source_id 过滤） |
| GET | `/api/v1/topics/{id}` | 详情 |
| POST | `/api/v1/topics/{id}/select` | 标记 selected |
| POST | `/api/v1/topics/{id}/scripts` | **SSE** 生成脚本，事件：`chunk`(原始增量)→`done`(完整校验后 Script)/`error` |
| PATCH | `/api/v1/scripts/{id}` | body `{content}`；存新版本并更新当前 |
| GET | `/api/v1/scripts/{id}` | 详情 |
| GET | `/api/v1/scripts/{id}/versions` | 版本列表 |
| POST | `/api/v1/scripts/{id}/revert` | body `{version}`；回退 |
| GET | `/api/v1/scripts/{id}/export?format=md\|txt` | 导出 |

SSE 约定：`chunk` 事件零到多次（`data: {"delta":"..."}`）→ 以 `done`（`data: {"script":{...}}`）或 `error`（`data: {"error":{"code","message"}}`）收尾；流中途失败必须 `error`，不静默断流、不回显堆栈。

## 八、Prompt 设计
- `summary_prompt`：输入=正文（截断 6000 字）+URL；输出 JSON `{title, summary, keywords[], is_official, credibility_score, video_potential_score}`。
- `topics_prompt`：输入=摘要+正文要点+内容方向（默认"AI 行业综合"）；输出 JSON `{topics:[{title, angle, one_liner, key_facts[], source_urls[], risk_flags[], score, score_breakdown{新鲜度,重要性,受众相关性,视频化潜力,观点空间,风险}, risk_level}]}`（3 个）。
- `script_prompt`：输入=选题+摘要+来源；输出 JSON `{content, fact_claims[], risk_flags[], source_urls[]}`；content 用 6 模块结构（开头钩子/背景/核心事实/观点/建议/结尾引导），60 秒。
- 格式约束三件套：Prompt 写正反例（`用 JSON，禁止在 JSON 外输出解释`）；`parser.py` 宽容解析（去 ``` 围栏、截取首尾大括号、容错尾逗号）；数量/内容约束不遵守记瑕疵，不反复重试烧钱。
- 事实核查规则（PRD 7.4）写入 script/topics prompt：优先官方来源、不足 2 源标"单一来源"、不确定不用确定语气、禁绝对化表达。

## 九、验收界面或纵向切片
- 需要最小验收界面（是临时验收工具，非正式前端）：单个 HTML 挂 `static/`，原生 JS + fetch + EventSource。功能上限：贴 URL、看摘要、看 3 个选题、选 1 个、看脚本流式生成、编辑保存、回退、导出。目标终端：桌面浏览器。

## 十、测试要求
- 第一层 mock 测试（离线，模型全 mock）：URL 校验与安全拒绝；正文清洗；宽容 JSON 解析器（多种坏格式）；摘要/选题/脚本生成的成功与模型失败/超时路径；状态流转；版本与回退；SSE 事件以 done/error 收尾（含无 Key 兜底）；导出格式；统一错误结构。
- 第二层真实冒烟（验收前）：贴 1 个真实 AI 行业链接 → 摘要 → 3 选题 → 脚本（SSE 计时）→ 编辑 → 导出，记录模型、耗时、成本、格式首测合规率；并按"待样例打分"用 5-10 条真实样例定 D2/D3。无 Key 时如实写"待验"。

## 十一、验收清单（产品经理照做）
- [ ] 打开 `http://127.0.0.1:8100/`，贴一个 AI 行业新闻链接，点"抓取并摘要"，能看到标题、摘要、关键词、可信度、视频化潜力。
- [ ] 点"生成选题"，看到 3 个候选选题，每个有标题/角度/看点/事实/来源/风险/评分。
- [ ] 选一个选题，点"生成脚本"，看到脚本文字逐步出现，最后完整脚本含来源引用和风险标注。
- [ ] 修改脚本保存，再改一版，能回退到上一版。
- [ ] 导出 Markdown 和纯文本，内容完整。

## 十二、风险与待确认项
- 网页抓取对 JS 渲染页/付费墙/反爬站点可能失败或正文不全 → 提示"抓取失败/正文过短"，支持手动粘贴正文兜底（后续 M2 可加）。
- 模型输出 JSON 偶发不合规 → 宽容解析 + 有限重试；仍失败统一报错，不烧钱。
- 选题/脚本质量、事实准确性 → 真实样例打分定标，本阶段不宣称"已达标"。
- 成本：文字调用按量计费，月护栏 ≤500 元已定。
- 待产品经理决定：无（选型已在适配声明交代，M3 前再报价确认）。
