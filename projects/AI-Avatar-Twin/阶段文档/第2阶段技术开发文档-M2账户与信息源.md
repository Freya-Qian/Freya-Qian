# 第 2 阶段技术开发文档｜M2 账户与信息源管理

> 配套文档：PRD V1.2（rev53）、《技术适配声明》、通用技术栈手册、第 2 阶段 M1 文档。
> 本文档只覆盖 M2。不提前实现视频渲染（M3）、正式前端（M4）。

## 一、阶段目标
- 交付范围（对齐 PRD 7.0 账户 / 7.1 Profile / 7.2 信息源 + 数据隔离）：
  1. 账户：手机号 + 验证码注册/登录（**本地验证码 mock**，短信服务后续接）、session token 鉴权、退出。
  2. 项目：创建 / 重命名 / 列表 / 切换。
  3. 数字人 Profile：创建 / 编辑 / 删除；字段 = 名称、形象类型（模板/本人照片，照片实际上传留 M3）、声音类型、表达风格、语言、口头禅、禁用词、内容方向、平台、视频比例。
  4. 信息源：URL / 手动文本 / RSS 三类；新增 / 禁用 / 删除 / 列表；手动触发抓取（复用 M1 fetch+摘要）→ 生成 SourceItem；同一链接去重。
  5. 数据隔离：SourceItem / Topic / Script / Source / Project / Profile 全部挂 `user_id`，接口层 + 存储层双重校验。
  6. 脚本生成接入 Profile 风格（语言 / 内容方向 / 口头禅 / 禁用词）。
- 阶段产物：后端（账户 + 数据隔离 + Profile + 信息源）+ 扩展现有验收界面 + mock 测试 + 真实冒烟。
- 验收标准：
  1. 可注册、登录、退出；未登录调用受保护接口被拒（401）。
  2. 用户 A 看不到用户 B 的信息源/选题/脚本（数据隔离实测）。
  3. 可创建/切换项目、增删改 Profile。
  4. URL / 手动 / RSS 三种信息源可新增、抓取、去重、禁用、删除。
  5. 脚本生成按所选 Profile 的风格与方向生成。
- 明确不做：真实短信服务（本地验证码）；本人照片实际上传与渲染（M3）；定时抓取（暂缓）；声音克隆/多平台（V1 不做）。
- 主链路片段：`注册登录 → 建项目 → 建 Profile → 建信息源 → 抓取 → 摘要 → 选题 → 脚本（按 Profile 风格）`。

## 二、技术适配摘要
- 沿用 M1：FastAPI + SQLite + SQLAlchemy + SSE + 单 HTML 验收界面。
- 本阶段启用：账户与鉴权（本地验证码 + 不透明 token）、数据隔离（user_id 全局）、信息抓取（URL/手动/RSS，RSS 用 feedparser）。
- 本阶段偏离/暂缓：真实短信服务暂缓（本地验证码 mock，上线前接）；定时抓取暂缓；照片实际上传留 M3。

## 三、技术栈与模型
- 复用 qwen-plus（脚本生成）；摘要/选题 prompt 不变；脚本 prompt 增加 Profile 参数。
- 新增依赖：`feedparser==6.0.11`（RSS 解析）。
- 鉴权：不透明 token（`secrets.token_urlsafe`），存 `auth_tokens` 表，带过期时间；每次请求经 `Authorization: Bearer <token>` 解析 user_id。

## 四、环境与配置
- `.env.example` 追加：
  ```dotenv
  DEV_MODE=true            # 本地开发：验证码直接返回给前端显示
  TOKEN_TTL_DAYS=7
  ```
- 需要用户提供：无新增（沿用已填的 MODEL_API_KEY）。
- 端口：后端 8100 不变。

## 六、数据、资产与状态
- 新表（字段对齐 PRD 9.0/9.0b/9.1）：
  - `users`：id、phone、created_at。
  - `auth_tokens`：token、user_id、created_at、expires_at。
  - `projects`：id、user_id、name、default_avatar_profile_id、status（active/archived）、created_at。
  - `avatar_profiles`：id、user_id、project_id、name、avatar_type（template/uploaded_self）、voice_type（default_tts）、style_tags(JSON)、language、catchphrases(JSON)、banned_phrases(JSON)、topic_preferences(JSON)、platform_preferences(JSON)、video_ratio、created_at、updated_at。
  - `sources`：id、user_id、project_id、source_type（url/manual/rss）、name、url、status（active/disabled）、created_at。
- 既有表加 `user_id`（SourceItem/Topic/Script），存量数据归入一个默认演示用户或清空（本地，清空重建即可，数据不迁移）。
- 状态机：Source `active/disabled`；Profile 无状态仅软删除（MVP 用真删 + 项目绑定校验）；抓取状态沿用 SourceItem `fetched/summarized/failed`。
- 数据隔离：所有查询 `WHERE user_id = 当前用户`，写操作校验资源归属；`project_id` 与 `user_id` 双重校验。

## 七、API / 工具设计（统一 `{"error":{"code","message"}}`，受保护接口需 Bearer token）

**账户**
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/auth/code` | body `{phone}`；生成 6 位验证码（DEV_MODE 下响应含 `dev_code`） |
| POST | `/api/v1/auth/verify` | body `{phone, code}`；校验通过则创建/登录用户，返回 `{token, user}` |
| POST | `/api/v1/auth/logout` | 吊销当前 token |
| GET | `/api/v1/auth/me` | 当前用户信息 |

**项目 / Profile / 信息源**
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST/GET | `/api/v1/projects` | 创建 / 列表 |
| PATCH | `/api/v1/projects/{id}` | 重命名 |
| POST/GET/PATCH/DELETE | `/api/v1/profiles` 等 | Profile CRUD |
| POST/GET | `/api/v1/sources` | 新增 / 列表（含抓取状态） |
| PATCH | `/api/v1/sources/{id}` | 禁用/启用/重命名 |
| DELETE | `/api/v1/sources/{id}` | 删除 |
| POST | `/api/v1/sources/{id}/fetch` | 手动抓取（URL/RSS）→ 生成 SourceItem |

**既有 M1 接口**：全部加 `user_id` 过滤与鉴权；脚本生成读所选 Profile。

## 八、Prompt 设计
- 摘要/选题 prompt 不变；脚本 prompt 增加 Profile 参数注入：`语言/表达风格/口头禅/禁用词/内容方向/时长`。形式：在 SCRIPT_USER 顶部加"你的账号人设"段，字段取 Profile；无 Profile 用默认（专业/中文/60秒）。

## 九、验收界面或纵向切片
- 扩展单 HTML：登录页 → 主界面（项目切换、Profile 编辑、信息源管理、沿用 M1 的 抓取→摘要→选题→脚本→导出 流程）。仍是临时验收工具，非正式前端。

## 十、测试要求

- RSS 源可能因站点反爬/格式差异抓取失败，失败进 `failed` 可重试。
- 待产品经理决定：无（选型已定，D1-D10 已落账）。
