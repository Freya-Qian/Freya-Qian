# 第 2 阶段技术开发文档｜M3 数字人视频与素材包

> 配套文档：PRD V1.2（rev53）、《技术适配声明》、通用技术栈手册、M1/M2 文档。
> 本文档只覆盖 M3。不提前实现正式前端（M4）、抖音授权发布（V1 不做）。

## 一、阶段目标
- 交付范围（对齐 PRD 7.6 视频生成 / 7.8 素材包 / 7.1 形象素材）：
  1. **照片上传**：数字人 Profile 上传本人照片（格式/真实类型/大小/安全文件名校验），记录授权状态。
  2. **异步视频任务**：脚本 → 生成 9:16 口播视频，队列状态（queued/rendering/success/failed），持久化可恢复。
  3. **TTS**：口播稿转配音（阿里云百炼 CosyVoice，`cosyvoice-v2` + 音色 `longxiaochun_v2`；未配 Key 时降级为静音）。
  4. **视频合成**：用户照片 → 图生图生成 3D 渲染风形象（wan2.6-image）→ 形象口型驱动（**即梦 OmniHuman**）→ MP4；失败降级 MoviePy。
  5. **字幕 SRT + 封面**：按句切分估算时长的 SRT；从视频抽帧或占位封面。
  6. **素材包 ZIP 导出**：MP4、封面、平台标题、简介、标签、来源清单、口播脚本、SRT。
  7. 标题/简介/标签用 LLM 从脚本生成（复用文字模型）。
- 验收标准：确认脚本后能生成视频、失败可重试、可预览、可下载完整素材包、异步任务有明确队列状态。
- 明确不做：自建 3D 数字人建模/自建 EchoMimic（未来降本）；声音克隆/多平台（V1 不做）；正式前端（M4）。
- 主链路片段：`脚本 → 建视频任务 → TTS → 照片风格化(3D渲染风) → 形象口型驱动 → SRT/封面 → ZIP 素材包 → 预览/下载`。

## 二、技术适配摘要
- 沿用 M2：FastAPI + SQLite + SQLAlchemy + token 鉴权 + 单 HTML 验收界面。
- 本阶段启用：长耗时任务持久化（VideoProject 表 + 后台执行）、本地文件目录（照片/音频/视频/导出）、上传文件校验。
- 数字人渲染：用户照片先经图生图风格化为 3D 渲染风形象（皮克斯质感、保留面部特征），再由口型驱动（火山即梦 OmniHuman）生成口播视频；任一环节失败降级 MoviePy「照片+音频+字幕」合成；TTS 未配 Key 时降级静音。

## 三、技术栈与模型
- 新增依赖：`moviepy==2.0.0`（视频合成）、`python-multipart==0.0.20`（文件上传）。
- 系统依赖：ffmpeg（本机已装 v6.0，MoviePy 依赖）。
- TTS：阿里云百炼 CosyVoice（`TTS_MODEL=cosyvoice-v2`、音色 `longxiaochun_v2`，`TTS_BASE_URL=https://dashscope.aliyuncs.com/api/v1`；**已真实跑通**）。
- 标题/简介/标签：复用 qwen-plus（新增一份 `packaging_prompt`）。

## 四、环境与配置
- `.env.example` 追加：
  ```dotenv
  TTS_ENABLED=true
  TTS_API_KEY=            # 留空复用 MODEL_API_KEY
  TTS_BASE_URL=https://dashscope.aliyuncs.com/api/v1
  TTS_MODEL=cosyvoice-v2
  TTS_VOICE=longxiaochun_v2
  DIGITAL_HUMAN_SEGMENT=60   # 单段音频上限（秒），30 秒脚本不切段
  SCRIPT_DURATION=30         # 口播脚本默认时长（秒），生成后硬截断到句末
  ```
- 需要用户提供：TTS 供应商 Key（可先复用 MODEL_API_KEY，若同平台同 Key）。无 Key 时 TTS 降级静音，视频仍可合成（照片+字幕+静音）。
- 资产目录（`backend/data/`）：`uploads/`（照片）、`audio/`、`videos/`、`exports/`（均 gitignore）。

## 六、数据、资产与状态
- `video_projects` 表（对齐 PRD 9.5）：id、user_id、script_id、avatar_profile_id、version、video_url、cover_url、subtitle_url、export_package_url、status（queued/rendering/success/failed）、error_message、created_at。
- `avatar_profiles` 加 `avatar_asset_id`（照片文件名）、`avatar_consent_status`（none/granted）。
- 资产规则：文件名用随机名 + 白名单扩展名；照片限 jpg/png/webp、≤5MB；视频/音频/导出落 `data/` 对应目录，元数据入表。
- 状态机：VideoProject `queued → rendering → success | failed`；失败可重试（重新提交任务）；服务重启后遗留 `queued/rendering` 标 `failed`（不自动重做）。

## 七、API / 工具设计（统一错误结构，均需 token）
| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/profiles/{id}/photo` | multipart 上传照片，校验格式/类型/大小，写授权状态 |
| POST | `/api/v1/scripts/{id}/videos` | 创建视频任务（queued），后台生成，返回 VideoOut |
| GET | `/api/v1/videos/{id}` | 查询任务状态与产物地址 |
| POST | `/api/v1/videos/{id}/retry` | 失败后重试 |
| GET | `/api/v1/videos/{id}/export` | 下载素材包 ZIP |
| GET | `/api/v1/videos/{id}/file` | 预览/下载 MP4 |

后台任务：单进程 asyncio 队列串行执行（M3 规模足够）；任务状态先落库再执行，崩溃可恢复。

## 八、Prompt 设计
- 新增 `packaging_prompt`：输入脚本 content + 选题标题 + 平台（抖音），输出 JSON `{title, description, tags[]}`（标题 ≤30 字、简介 ≤100 字、标签 3-5 个）；带格式约束与禁止绝对化表达规则。

## 十二、风险与待确认项
- TTS 已真实跑通（cosyvoice-v2 / longxiaochun_v2）。
- 数字人渲染 = 火山即梦 OmniHuman（1 元/秒，200 秒免费试用），单条 30 秒约 30 元；照片→3D 风格化（wan2.6-image）已接入验证。规模化需自建 EchoMimic 降本（见《MVP快速上线与数字人降本方案》）。
- 即梦单段生成约 5-10 分钟且串行排队，30 秒脚本单段生成（切段上限 60 秒），避免拼接割裂。
- 待产品经理决定：无（TTS 用阿里云百炼、数字人先第三方 API 验证的路线已确认）。

## 十四、实施完成记录（2026-09-20 补充）
- **数字人方案切换**：从阿里云万相-数字人（wan2.2-s2v）切换到火山引擎即梦 OmniHuman——原因是阿里云 s2v 自带烧录字幕+水印且 API 无关闭参数；即梦无字幕水印、不镜像、有声音、分辨率更高。鉴权用 AK/SK V4 签名（官方 SDK）。
- **照片→3D 风格化**（D11）：新增 `stylize.py`，用通义万相 wan2.6-image 参考生图，把照片转成 3D 渲染风形象；失败自动降级原照片；本地 hash 缓存。
- **口播稿硬截断**：脚本生成后按目标时长（30 秒约 150 字）截断到句末，避免模型超字数导致配音超长。
- **TTS 去标记**：配音前去掉【开头钩子】等结构标记，不念出来。
- **切段上限 60 秒**：30 秒脚本单段生成、不拼接，解决衔接割裂；过滤过短分段（<1.5 秒尾巴）避免数字人接口报错。
- **成本**：即梦 1 元/秒（200 秒免费试用），30 秒约 30 元；规模化降本路线见《MVP快速上线与数字人降本方案》。
