# 技术适配声明

> 项目：AI Avatar Twin｜阶段 1 技术适配｜日期：2026-09-20
> 依据：PRD V1.2（rev 53）+ 通用手册第一、二、三、四、五、六节

## 1. 产品形态判断
- 产品类型与核心任务：分阶段确认的多媒体创作 Agent——AI 行业信息源 → 选题 → 口播脚本 → 数字人口播视频 → 发布素材包导出；每个环节用户审核确认后进入下一步。
- 核心交互：分阶段确认 + 异步生成（脚本流式、视频分钟级异步）。
- 开发路径：**纵向切片（路径 B）**。理由：脚本质量和视频质量必须"用眼睛看、亲手操作"才能判断，人工确认（PRD 7.7）本身是产品核心体验，不能只靠 JSON 和自动化测试验收。
- 当前阶段范围：阶段 2 后端 MVP，拆 4 个子阶段：

| 子阶段 | 内容 | 验证重点 |
| --- | --- | --- |
| M1 文字核心闭环 | 手动 URL → 抓取摘要 → 选题（评分/风险/来源）→ 脚本生成（含引用）→ 编辑/版本 → Markdown 导出 | AI 核心质量（信息→选题→脚本） |
| M2 账户与信息源 | 注册登录（手机号验证码，短信暂用本地验证）→ 项目 → 数字人 Profile → RSS/URL 信息源管理 → 数据隔离 | 多用户隔离、Profile 配置 |
| M3 数字人视频 | TTS + 数字人渲染 + 视频预览 + 素材包（ZIP）导出 | 视频链路与外部计费服务 |
| M4 正式前端 | Web 端 Next.js 完整界面 | 桌面/手机适配 |

## 2. 采用的默认方案
- 后端：Python + FastAPI + Pydantic + pytest（手册默认栈）。
- 数据库：SQLite + SQLAlchemy（触发条件：用户账户、多实体关系、数据隔离、版本管理均命中）。
- 文字模型：阿里云百炼 DashScope（OpenAI 兼容，qwen 系列）——复用「脑洞游戏」同平台，不新增平台、不新增 Key 体系。
- 前端终端：Web 端 Next.js + TypeScript + Tailwind（阶段 3 正式前端）。
- 阶段 2 验收界面：单个 HTML 挂 FastAPI `static/`（最小验收界面，不提前铺正式前端）。
- 流式：脚本生成用 SSE；视频生成用"提交 + 查询状态"轮询。

## 3. 触发的按需模块
- SQLite + SQLAlchemy：多实体/账户/隔离 → 引入（M1 起，暂缓 Alembic）。
- 持久化任务记录 + 队列状态：视频生成（分钟级）→ 引入（M3；先单进程，达规模阈值再上任务队列）。
- 本地文件目录：本人照片/视频/封面/素材包 → 引入（M3；生产阶段评估对象存储）。
- SSE：脚本流式生成 → 引入（M1）。
- 上传文件校验：本人照片（格式/真实类型/大小/安全文件名/内容安全）→ 引入（M2）。
- 信息抓取：手动 URL / RSS 解析 → 引入（M1 手动 URL，M2 加 RSS）。

## 4. 偏离或暂缓的默认方案
| 默认方案 | 替代/暂缓 | 原因 | 影响 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| TTS + 数字人渲染（手册栈外外部计费服务） | 先第三方 API 验证、后自建 EchoMimic 降本 | PRD 18.1 已定路线 | 接入前单独报价确认（底线 8），M3 才真正调用 | M3 开工前 |
| 短信验证码（真实短信服务） | M2 用本地验证码/mock | 企业认证暂不能办，个人接短信服务受限 | 不影响 M2 开发与验收 | 上线前接真实短信 |
| Alembic 数据库迁移 | 暂缓，MVP 用 create_all | MVP 单库起步 | 生产前补迁移 | 生产上线前 |
| PostgreSQL | 暂缓，先 SQLite | MVP 几十人内部试用 | 生产评估切换 | 用户量/并发增长时 |
| 定时抓取（每日 2 次） | 暂缓，先手动触发 | 先验证闭环再上调度 | 不影响闭环验证 | 上线时上调度 |
| 抖音授权发布 / 声音克隆 / 多平台 / 联网搜索 | V1 不做 | PRD 已明确后置 | 无 | V1.1/V2 |

## 5. 强制底线检查
- 密钥与隐私：通过——.env 不入库、不回显；肖像/声音仅国内存储，V1 禁真实他人形象/声音。
- 数据与任务可恢复：通过——SQLite + 持久化任务记录，重启可恢复。
- 输入输出校验：通过——Pydantic + 模型结构化输出校验 + 上传文件校验。
- 错误与日志边界：通过——统一 `{"error":{"code","message"}}`，不泄露堆栈，不记密钥/完整文档。
- 测试与真实模型验收：mock 自动化测试先行 + 真实模型冒烟；无 Key 时如实写"待验"。
