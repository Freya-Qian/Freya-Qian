# AI Avatar Twin · Agent 化改造方案

> 项目：AI Avatar Twin｜日期：2026-09-21
> 定位变更：数字人短视频工具 → **Agent + Harness 产品**（模型为驾驶者，Harness 为载具）
> 依据：agent-blueprint 方法论（s01 Agent Loop + s02 工具系统 + 17 组件）
> 配套：`AI Avatar Twin-Agent Harness评审与优化方案.md`（差距 A~G）

---

## 一、目标与定位

把 AI Avatar Twin 从「用户一步步点按钮的固定流水线」升级为「**用户给一个目标，Agent 自主完成**」的 Agent 产品。

```
改造前：用户贴链接 → 点摘要 → 点选题 → 选一个 → 点脚本 → 点视频（5 步手动）
改造后：用户说"帮我做一期关于 XX 的犀利风格短视频" → Agent 自主完成
```

核心变化：**模型从"被调用的工具"变成"驾驶者"**，自主决定每一步做什么。

---

## 二、Agent Loop 设计（s01）

**形态：单 Agent 循环**（MVP 够用，不引入多 Agent）。

```
用户给目标（链接或主题）
   ↓
Agent Loop（messages → model → tool_use → 结果 → 循环）
   ↓ 模型自主决策，反复调用工具：
   fetch_source（抓取）
   summarize（摘要）
   generate_topics（选题）
   fact_check（事实核查）
   generate_script（脚本）
   evaluate（自检，不达标重写）
   ↓
达到目标（产出合格脚本）→ 停下，交还用户
```

**循环终止条件（s17 目标闭环）**：
- 产出脚本通过质量评估器 → 成功终止
- 达到最大步数（防死循环，建议 ≤ 20 步）→ 交还用户，附当前进度
- 工具连续失败 → 降级交还用户

## 三、工具池（s02）——现有能力全部注册成工具

| 工具名 | 输入 | 输出 | 副作用 | 权限 | 备注 |
|---|---|---|---|---|---|
| `fetch_source` | url | 正文/标题 | 网络请求 | allow | 复用 fetcher |
| `summarize` | 正文 | 摘要/关键词/可信度 | 调模型 | allow | 复用 engine |
| `generate_topics` | 摘要 | 3 个选题 | 调模型 | allow | 复用 engine |
| `fact_check` | 选题+事实 | 来源标注/风险 | 调模型 | allow | 复用现有兜底 |
| `generate_script` | 选题 | 口播脚本 | 调模型 | allow | 复用 engine |
| `evaluate_script` | 脚本 | 通过/不通过+理由 | 调模型 | allow | 新增（s17） |
| `generate_video` | 脚本 | 视频任务 | **花钱+耗时** | **ask（需用户确认）** | 复用 video_worker |
| `export_package` | 视频 | 素材包 | 写存储 | allow | 复用 packaging |

**关键设计**：
- 文字类工具（抓取/摘要/选题/核查/脚本/评估）→ **Agent 自主调用**（便宜、可重试、无副作用）
- 花钱/发布类工具（视频生成、发布）→ **必须用户确认**（Agent 不能自主触发）

## 四、Agent 自主边界（红线）

| 操作 | Agent 能否自主 | 原因 |
|---|---|---|
| 抓取、摘要、选题、核查、脚本、评估 | ✅ 自主 | 便宜、可重试、无破坏性 |
| 生成视频 | ❌ 需用户确认 | 花钱（即梦 30 元/条）、耗时（5-10 分钟） |
| 发布到平台 | ❌ 需用户确认 | PRD 7.7 红线，未经确认不发布 |
| 访问他人数据 | ❌ 禁止 | 数据隔离（user_id），工具层强制校验 |
| 删除数据 | ❌ 需用户确认 | 破坏性操作 |

**实现方式**：工具元信息带 `permission: allow | ask`，Agent Loop 在调用 `ask` 类工具前，先交还控制权给用户确认（对齐 s03 权限系统）。

## 五、系统提示词设计（Agent 身份）

```
你是 AI 行业短视频的选题与脚本助手（Agent）。

【你的目标】
用户给你一个链接或主题，你自主完成"抓取→摘要→选题→事实核查→脚本"，
产出符合用户数字人风格的 60 秒口播脚本，直到自检合格为止。

【你的工具】
fetch_source / summarize / generate_topics / fact_check /
generate_script / evaluate_script（这些你可以自主调用）
generate_video / export_package（这些必须用户确认后才调用）

【你的规则】
1. 事实核查：脚本每条事实必须有来源，不确定的用"据报道/可能"；
   禁止编造数字/机构/第一人称实测。
2. 风格遵循：严格按用户 Profile 的（风格/口头禅/禁用词/内容方向）。
3. 自主决策：证据不足就多抓几个源；脚本自检不合格就重写，最多重试 2 次。
4. 边界：生成视频和发布必须等用户确认；只能访问当前用户自己的数据。
5. 停止条件：脚本自检通过即停下交还用户；不确定就问用户，不硬编。

【输出】
每次循环输出：下一步要调的工具 + 参数（或"已完成"）。
```

## 六、质量评估器（s17 目标闭环）

新增 `services/evaluator.py`，Agent 每生成一版脚本后自动自检：

| 判定维度 | 规则 |
|---|---|
| 回应选题 | 脚本是否围绕选题角度，不跑题 |
| 事实有据 | fact_claims 是否都能追溯来源 |
| 语言质量 | 通顺、符合风格、无编造表述 |
| 长度合适 | 约 60 秒口播（200-300 字） |

- 通过 → Agent 停下，交还用户
- 不通过 → 附理由，Agent 自主重写（最多 2 次）
- 仍不通过 → 标 risk_flag「质量待人工审核」，交还用户

**验收**：脚本生成后能自动判定质量，不合格自动重写，通过率可统计（对齐 D2/D3）。

## 九、实施步骤（分阶段）

### H1（Agent 最小闭环，2-3 周）
1. 新增 tools.py（8 个工具注册）+ agent.py（Agent Loop）
2. 新增 AGENT_SYSTEM_PROMPT
3. Agent 自主完成「抓取→摘要→选题→核查→脚本→自检」，视频仍走用户手动确认
4. 新增 `/agent/run` SSE 接口
5. 验收：给一个链接，Agent 自主产出合格脚本（含来源引用+风险标注）

### H2（补齐组件，1-2 周）
6. 记忆系统（UserPreference，选题偏好）
7. 内容 guard（敏感拦截）
8. 钩子系统（埋点统一）
9. 验收：Agent 记住用户偏好、敏感内容被拦、埋点齐全

### H3（目标闭环 + 指标，1 周）
10. 评估器接入（自检重写）
11. 指标采集（时延/成功率/成本）
12. 验收：脚本合格率可统计，不合格自动重写

## 十、风险与待确认

| 风险 | 应对 |
|---|---|
| Agent 死循环/步数失控 | 最大步数限制（≤20），超限交还用户 |
| Agent 花钱失控 | 视频生成是 ask 权限，Agent 不能自主触发 |
| Agent 幻觉/编造 | 保留现有 `_detect_fabrication` 兜底 + 评估器自检 |
| 改造破坏现有流水线 | 新旧接口并行，原手动流程保留 |
| 模型自主决策质量不稳 | 单 Agent + 明确系统提示词 + 评估器兜底，MVP 够用 |

**已确认（2026-09-21）**：
1. Agent 入口交互形态 = **一句话目标输入框 + 进度展示**（非对话式，MVP 简单）。
2. Agent 文字闭环允许自主抓取多个源，**每次抓取上限 3 个**（超出需用户确认）。
