竞品：WorkBuddy，证据卡 6 张

[定位生成耗时 21.1s，状态 success]
一句话定位： 一款面向 Web 端的产品经理的 AI 产品工厂，专注支持单人从产品想法到可交付原型的端到端孵化流程，不覆盖通用办公或团队协作场景。
目标用户： 独立产品经理、初创团队中的产品负责人、需快速验证 MVP 的个体创业者
核心价值主张： 让产品想法在 Web 端完成结构化拆解、阶段化执行与结果验收，全程本地化轻量运行，无需登录、无需云端依赖，确保隐私与交付确定性。
差异化（含证据引用）：
  - Web 端单机轻量产品孵化工作台，所有流程数据本地运行，无账号体系与云端同步  [证据: WB-E4]
  - 以‘产品想法孵化’为唯一主入口，拒绝多专家矩阵或领域泛化，聚焦产品定义→原型交付闭环  [证据: WB-E3]
  - 采用固定四阶段流水线（洞察→定义→设计→验证）+ 每阶段专属 Agent，输出物明确可验收，非自由对话式探索  [证据: WB-E2]
对比表：
  · 定位：WorkBuddy=全场景 AI 办公工作台/智能体桌面工作台｜我们=Web 端产品孵化专用工作台
  · 用户：WorkBuddy=泛办公人群（含运营、HR、销售等多角色）｜我们=聚焦独立产品经理及 MVP 验证者
  · 场景：WorkBuddy=日常办公任务托管与跨角色协同｜我们=单人主导的产品概念到可交付原型的闭环孵化
  · 流程：WorkBuddy=自由任务发起 + 多 Agent 并行调度｜我们=强制四阶段流水线，每阶段仅一个专职 Agent 接入
  · 输出物：WorkBuddy=泛化任务结果（如会议纪要、周报、摘要）｜我们=结构化交付物：用户痛点地图、PRD 草稿、低保真原型图、可用性测试方案
  · 协作：WorkBuddy=项目空间 + 多 Agent 权限边界｜我们=暂不支持协作，保留项目空间扩展位（待补证）
  · 集成：WorkBuddy=Slack/飞书/钉钉/微信等深度连接器｜我们=仅支持飞书复制友好格式导出（不调 API），GitHub issue 草稿生成（不调 API）
  · 差异机会：WorkBuddy=广度优先：覆盖办公全链路｜我们=深度优先：在产品定义环节做结构化、可验收、零依赖的 Web 端闭环
不做什么： 不支持团队协作、不提供内容库/知识库、不接入外部 API、不生成代码或部署服务、不覆盖需求管理以外的项目管理职能（如排期、预算、ROI）
