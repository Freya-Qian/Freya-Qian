## 一、背景与产品决策

产品经理澄清真实诉求：

1. **WorkBuddy 只是做"AI 产品工厂"这个项目的参照，不在产品中体现**——产品是通用的竞品分析工作台，不硬编码 WorkBuddy。
2. 竞品不会只有一个，MVP 支持**最多 3 个竞品**（指**用户自己项目的竞品**）。
3. 用户输入竞品名称（可选填官网 URL），后台抓取相关内容并结构化分析。
4. 网页端工作台形式，流程串联、体验丝滑。

已拍板：

| 决策项 | 结论 |
|---|---|
| WorkBuddy | **彻底移除**：不作为种子数据 / 示例模板 / 对比表硬编码 / 界面文案，仅作者设计参照 |
| 竞品数量上限 | **MVP ≤ 3 个**（用户自己项目的竞品） |
| MVP 抓取方式 | 贴网址抓取（名称 + 可选官网 URL） |
| 名称自动搜索 | 放 V1（需搜索 API） |
| 抓取证据置信度 | 固定"合理推断" |

## 四、V1 展望（名称自动搜索，不在 MVP）

```
用户输入竞品名称 → 搜索 API → top 结果去重过滤 → 抓取 1~3 网页 → LLM 生成证据卡（置信度=合理推断）
```
- 搜索 API Key 用户可选配，未配置回退"贴网址"；选型与成本 V1 前再定。

---

## 五、验收标准（MVP）

1. 产品中**无任何"WorkBuddy"字样**（代码/界面/文案）。
2. 一个项目最多添加 **3 个竞品**，超出拦截提示。
3. 每个竞品可贴 URL 抓取生成证据卡（来源/结论/启发/置信度）。
4. 多竞品抓取完成后生成**多竞品对比表**（维度含定位/用户/场景/流程/输出物/协作/集成/差异机会）。
5. 竞品分析 → 定位 → PRD 流程顺畅串联。
