## 一、评审结论（是否 agent+harness）

- 本项目是 **agent+harness 项目**，形态为 **s16 固定阶段流水线**：模型（qwen-plus）只做"每阶段单次结构化生成"，编排/持久化/校验/错误处理全靠代码（harness）。
- 按 Harness 五要素（工具/知识/观察/行动/权限）评估当前 M1 完成度：

| 组成 | 状态 |
|---|---|
| 模型（智能） | ✅ 已接入（`core/llm.py`，超时/重试/统一错误） |
| 工具 Tools | ❌ 无（模型不调工具，M2 起引入） |
| 知识 Knowledge | ⚠️ 雏形（`services/prompts.py` 8 问/摘要模板） |
| 观察 Observation | ⚠️ 雏形（`Task` 状态流转） |
| 行动 Action | ❌ 无（写库为后端硬编码，非模型触发） |
| 权限 Permissions | ❌ 无（统一错误处理 ≠ 权限，M2 起补） |

> 结论：**"模型 + 1/5 harness"**，属正常推进中的 M1 半成品，不是缺陷；下述待修项是让 M1 达到"可落地"标准所需的生产级硬化。

## 三、修法细节（按文件）

### `services/clarify.py`
```python
# generate_questions：解析失败 → 全量兜底
try:
    data = extract_json(text)
    questions = _normalize_questions(data.get("questions"))
except LLMError:
    questions = [{"dimension": d, "question": DEFAULT_QUESTIONS[d]["question"],
                  "hint": DEFAULT_QUESTIONS[d]["hint"]} for d in DIMENSIONS]
```

### `services/clarify.py`（摘要纠错重试，可下沉到 `core/llm.py`）
- 首次 `extract_json` 失败时，把错误信息拼进 user prompt 再调一次 `client.complete`；二次失败才抛 `PARSE_ERROR`。

### `api/routes.py`（幂等）
- `start_clarify_questions` / `start_brief` 创建 Task 前先查询：
```python
existing = (db.query(Task)
    .filter(Task.project_id == project.id,
            Task.task_type == "clarify_questions",
            Task.status.in_(["queued", "processing"]))
    .first())
if existing:
    raise LLMError("CONFLICT", f"已有进行中的任务 {existing.id}")
```

### `api/routes.py`（必答项）
- `submit_clarify_answers` 或 `start_brief` 前校验关键项；缺则 `LLMError("INVALID_INPUT", "必答项未填：目标用户/场景/成功指标")`。

### `app/main.py`（优雅关闭）
- lifespan 增加 shutdown：设置停止标志 → `task_worker.stop_worker()` → 等待当前任务 → 剩余 queued 标 failed。
