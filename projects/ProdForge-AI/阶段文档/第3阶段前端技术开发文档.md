## 一、阶段目标与范围

把阶段 2 的最小 HTML 验收界面（`backend/app/static/index.html`）升级为正式前端三栏工作台，对接已就绪的后端 API，达到 PRD 第 9 章「Web 端信息架构」的形态，可进入产品评审。

- **做**：正式前端（项目列表、三栏工作台、10 个核心页面、异步任务交互、错误/预算提示）。
- **不做**：不改后端接口与数据模型（R2/R3/R4 可后置项不在本阶段）；不做登录（MVP 匿名本地用户）；不做飞书/GitHub 真实 API 同步（V1）。

## 二、技术栈与工程搭建

| 项 | 决策 |
|---|---|
| 框架 | Next.js（App Router）+ TypeScript + Tailwind |
| 端口 | 前端 **3300**；后端 8200（与「脑洞游戏」3000/8000、「AI Avatar Twin」3300/8100 隔离） |
| 后端地址 | `http://127.0.0.1:8200/api/v1` |
| 跨域 | 后端**未配 CORS**。二选一：①后端 `main.py` 加 `CORSMiddleware`（本地单机无安全顾虑，最省事）；②Next.js `next.config` rewrites 把 `/api/*` 代理到后端（推荐，生产同域更自然）。本阶段默认走 ② |

```ts
// next.config.ts（方案②，前端不感知 8200）
async rewrites() {
  return [{ source: "/api/:path*", destination: "http://127.0.0.1:8200/api/:path*" }]
}
```

启动：`cd frontend && npm run dev`（3300）；后端照旧 `cd backend && .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8200`。

## 四、状态机与交互协议

### 4.1 阶段枚举（后端 `Project.current_stage`）

```
idea → clarify → competitor → position → prd → tasks → package
```

- 新建项目后 `current_stage` 默认 `clarify`。
- 每阶段「确认」后由后端推进：摘要确认→`competitor`；定位确认→`prd`；PRD 确认→`tasks`；任务确认→`package`。
- **前端不要自己推进阶段**，一律以 `GET /projects/{id}` 返回的 `current_stage` 为准，阶段栏高亮由它驱动。

### 4.2 异步任务三态协议（PRD 长文档/慢操作）

后端所有「生成」类端点都是**异步**：返回 `202` + `TaskOut`，前端轮询直到完成。

```
1. POST /projects/{id}/prd  →  202 {"id":"task_xxx","status":"queued",...}
2. 轮询 GET /tasks/{task_id}  →  status ∈ queued/processing/success/failed
3. success → 刷新对应数据（GET /prd 等）；failed → 展示 error 字段
```

- 轮询间隔建议 2s，超时上限按阶段设（澄清/摘要/定位 60s，PRD 180s，任务 120s）。
- `result_json` 是各阶段原始结果（字符串），前端**不要直接解析它做展示**，展示一律用各阶段的 `GET` 端点（结构化 schema）。

### 4.3 统一错误格式

所有非 2xx 响应：

```json
{ "error": { "code": "NOT_READY", "message": "请先完成并确认产品定位（第 4 步）" } }
```

| code | HTTP | 前端处理 |
|---|---|---|
| NOT_READY / CONFLICT | 409 | 提示「请先完成上一步」/「已有进行中任务」 |
| INVALID_INPUT / INVALID_URL / CONTENT_TOO_SHORT | 422 | 表单级错误提示 |
| BUDGET_EXCEEDED | 402 | 醒目提示「已超单项目预算」，引导降低重试 |
| NO_API_KEY | 503 | 引导去「设置」页填 API Key |
| TIMEOUT / NETWORK / MODEL_ERROR / PARSE_ERROR / FETCH_* | 502/504 | 提供「重试」按钮 |

## 五、API 契约（34 个端点，按链路分组）

### 5.1 冷启动与项目

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|---|---|---|---|---|
| GET | `/samples` | 3 个示例想法 | — | `[{name, idea}]` |
| POST | `/projects` | 新建项目 | `{name, idea, goal_type}` | `ProjectOut` |
| GET | `/projects` | 项目列表 | — | `ProjectOut[]` |
| GET | `/projects/{id}` | 项目详情 | — | `ProjectOut` |

`goal_type` 枚举：`course`（课程作业）/ `portfolio`（作品集）/ `real`（真实开发）/ `team_review`（团队评审）。

### 5.2 需求澄清

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|---|---|---|---|---|
| POST | `/projects/{id}/clarify/questions` | 生成 8 问 | — | `TaskOut`（异步） |
| GET | `/projects/{id}/clarify/questions` | 问题列表 | — | `QuestionOut[]`（含 `round_num/dimension/question/hint/answer/skipped/required`） |
| POST | `/projects/{id}/clarify/answers` | 提交回答 | `{answers:[{question_id, answer}]}` | `QuestionOut[]` |
| POST | `/projects/{id}/brief` | 生成摘要 | — | `TaskOut`（异步） |
| GET | `/projects/{id}/brief` | 需求摘要 | — | `BriefOut`（10 字段） |
| PUT | `/projects/{id}/brief` | 编辑 / 确认 | `BriefFields + {confirm}` | `BriefOut` |

`BriefOut` 字段：`one_liner/target_users/scenarios/pains/goals/non_goals/success_metrics/external_systems/knowledge_sources/open_questions`。

### 5.3 竞品证据

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|---|---|---|---|---|
| GET | `/projects/{id}/competitors` | 竞品列表 | — | `CompetitorOut[]` |
| POST | `/projects/{id}/competitors` | 添加竞品（≤3） | `{name, url?, positioning?, ...}` | `CompetitorOut` |
| POST | `/projects/{id}/competitors/recommend` | LLM 推荐竞品 | — | `TaskOut`（异步，结果在 result_json.competitors） |
| GET | `/projects/{id}/competitors/{cid}/evidences` | 证据卡列表 | — | `EvidenceOut[]` |
| POST | `/projects/{id}/competitors/{cid}/evidences` | 手动加证据卡 | `EvidenceCreate` | `EvidenceOut` |
| POST | `/projects/{id}/competitors/{cid}/evidences/fetch` | 贴网址抓取 | `{url, source_type}` | `TaskOut`（异步） |
| PATCH | `/projects/{id}/competitors/{cid}/evidences/{eid}` | 编辑证据卡 | `EvidenceUpdate`（字段可选） | `EvidenceOut` |
| DELETE | `/projects/{id}/competitors/{cid}/evidences/{eid}` | 删除证据卡 | — | — |

- 竞品上限 **3**（超出后端返回 CONFLICT，前端超 3 个时「添加」置灰）。
- `source_type` 枚举：官网 / 官方文档 / 公开文章 / 用户输入（贴网址抓取下单时由用户选）。
- `evidence_type` 枚举：定位/功能/流程/集成/输出物/定价/用户/限制。

### 5.4 产品定位

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|---|---|---|---|---|
| POST | `/projects/{id}/positioning` | 生成定位 | — | `TaskOut`（异步） |
| GET | `/projects/{id}/positioning` | 定位详情 | — | `PositioningOut` |
| PUT | `/projects/{id}/positioning` | 编辑 / 确认 | `{one_liner?, target_users?, value_proposition?, non_goals?, confirm}` | `PositioningOut` |

`PositioningOut` 含 `differentiators[]`（差异点）、`comparison[]`（多竞品对比表）、`evidence_refs[]`（证据引用）。

### 5.5 PRD

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|---|---|---|---|---|
| POST | `/projects/{id}/prd` | 生成 PRD | — | `TaskOut`（异步） |
| GET | `/projects/{id}/prd` | PRD 详情 | — | `PrdOut` |
| PUT | `/projects/{id}/prd` | 编辑章节 / 确认 | `{sections?, confirm}` | `PrdOut` |

`PrdOut.sections` 是 `[{title, content, status?, evidence_refs?}]` 列表（11 章节），含「待确认」标记与证据引用，前端按章节渲染 + 可编辑。

### 5.6 研发任务拆解

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|---|---|---|---|---|
| POST | `/projects/{id}/tasks` | 生成任务 | — | `TaskOut`（异步） |
| GET | `/projects/{id}/tasks` | 任务列表 | — | `DevTaskOut[]` |
| PATCH | `/projects/{id}/tasks/{task_id}` | 编辑单个任务 | `DevTaskUpdate`（字段可选） | `DevTaskOut` |
| DELETE | `/projects/{id}/tasks/{task_id}` | 删除任务 | — | — |
| PUT | `/projects/{id}/tasks` | 确认任务（→package） | — | `{current_stage}` |

`DevTaskOut`：`module`（前端/后端/AI/数据/集成/测试）、`priority`（P0/P1/P2）、`acceptance_criteria`、`dependencies[]`、`source_refs[]`。

### 5.7 迭代记录（记忆系统）

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|---|---|---|---|---|
| POST | `/projects/{id}/feedback` | 录入反馈 | `{content, affected_sections?, author_type?}` | `FeedbackOut` |
| GET | `/projects/{id}/feedback` | 反馈列表 | — | `FeedbackOut[]` |
| GET | `/projects/{id}/decisions` | 决策台账（项目 + 系统级） | — | `DecisionLogOut[]` |

### 5.8 资料包导出

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|---|---|---|---|---|
| POST | `/projects/{id}/export` | 导出资料包 | `{channel}` | `ExportResult{export_id, channel, title, content}` |

`channel`：`markdown` / `feishu_copy` / `github_issue`。前端拿 `content` 做「复制」或「下载为 .md」。

### 5.9 任务状态轮询

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/tasks/{task_id}` | 任务状态（queued/processing/success/failed + error + result_json） |

### 5.10 设置（模型配置，⚠️ 后端待补齐，见《设置页模型配置打通方案.md》）

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|---|---|---|---|---|
| GET | `/settings/model` | 当前模型配置（Key 只回尾 4 位） | — | `{configured, model_api_key尾4, model_name, model_base_url}` |
| PUT | `/settings/model` | 保存模型配置（写 .env + 热生效） | `{model_api_key, model_name?, model_base_url?}` | 同 GET |

> 这两个端点是阶段 3 配套新增，目前后端未实现；前端可先按此契约开发设置页，后端按方案文档补齐后联调。

## 六、页面级需求要点

### 项目列表页
- 展示名称、`current_stage`（转中文）、`status`、`updated_at`。
- 「新建项目」→ 新建页；「打开」→ 工作台概览。

### 新建项目页
- 3 个示例想法一键填入（`GET /samples`）；`goal_type` 四选一；填写名称 + 一句话想法。
- 提交后拿到 `project.id`，跳 `/projects/[id]`（进入澄清阶段）。

### 需求澄清页（clarify）
- 「生成澄清问题」→ 异步；渲染 8 问（问题 + 提示 + 必答标记）。
- 逐条回答、可跳过（跳过项标「待确认」）；「保存回答」→ 「生成需求摘要」→ 摘要 10 字段可编辑 → 「保存并确认」进竞品。

### 竞品分析页（competitor）
- 添加竞品（≤3，名称 + 可选 URL）；「贴网址抓取」生成证据卡（下单选 source_type）；「LLM 推荐竞品」。
- 每竞品一张证据卡列表（可编辑/删除）；对比表与差异点在「产品定位」页生成。

### 产品定位页（position）
- 「生成定位」→ 异步；展示一句话定位 / 目标用户 / 价值主张 / 差异点（含证据引用）/ 对比表 / 不做什么；可编辑 → 「保存并确认」进 PRD。

### PRD 页（prd）
- 「生成 PRD」→ 异步（约 34s，轮询）；11 章节渲染（含「待确认」标记与证据引用高亮）。
- 章节可编辑 → 保存后后端重新跑证据引用审计 → 「确认」进任务拆解。

### 任务拆解页（tasks）
- 「生成任务」→ 异步；任务列表（模块/优先级/验收/依赖/来源），P0 高亮。
- 单任务可编辑（PATCH）/删除（DELETE）；「确认任务」（后端校验 P0 存在 + 数量 ≥5）进资料包。

### 资料包页（package）
- 三通道导出按钮（Markdown 下载 / 飞书复制 / GitHub issue 复制）；展示「导出记录」。

### 迭代记录页（横向 Tab）
- 反馈录入框 + 反馈列表（content + author_type + 时间）；决策台账列表（decision + source + 时间）。

### 设置页
- 模型配置：API Key / 模型名 / Base URL（详见《设置页模型配置打通方案.md》）。核心交互：`GET /settings/model` 回显尾 4 位 + 状态；`PUT /settings/model` 保存并热生效（无需重启）；无 Key 时生成类接口返 503 → 引导去设置页。
- 数据导出/导入占位；关于。

## 七、非功能需求

| 项 | 要求 |
|---|---|
| 加载态 | 所有异步生成用「提交 + 轮询」模式，展示进度（阶段名 + 已耗时）；PRD/任务生成期间禁用「再次生成」防重复提交（后端幂等返回 409，前端也应防抖） |
| 错误提示 | 顶部 banner 统一展示 `error.message`；402 预算、503 无 Key 用醒目样式 |
| 时延预期 | 澄清 15–35s（略超 PRD 17.1 的 15s，产品经理按现状接受）；PRD ≤3min；需在 UI 明示「生成中，请稍候」 |
| 阶段门禁 | 未确认上一阶段时，下一阶段按钮置灰并提示「先完成上一步」（配合后端 409） |
| 响应式 | 三栏在窄屏可折叠（阶段栏抽屉化）；桌面优先 |

## 八、验收标准

1. 一条命令起前端（`npm run dev`）并能连上后端 8200，完成「新建项目 → 澄清 → 摘要 → 竞品 → 定位 → PRD → 任务 → 导出」全链路。
2. 阶段门禁生效：未确认上一阶段，下一阶段不可点且后端 409 有提示。
3. 异步任务轮询正常：生成中显示进度，成功刷新数据，失败展示错误并可重试。
4. PRD 11 章节渲染正确，「待确认」标记与证据引用可见、可编辑。
5. 三通道导出可用（下载 .md / 复制飞书格式 / 复制 GitHub issue 格式）。
6. 迭代记录页能录入反馈、查看决策台账。
7. 桌面 + 移动端宽度检查通过（有正式界面后必查）。

## 九、交接与风险

- **后端契约已冻结**（34 端点 + schema 见第五节），前端开发以本文档为准，不反推 `index.html`。
- 遗留可后置项（不在本阶段）：R2 hooks 空框架、R3 导出未落盘、R4 飞书通道与 markdown 无差异。
- 待产品经理定夺：8 问耗时 SLA（现 15–35s vs PRD 15s）——影响澄清页 loading 文案与轮询超时设置。
- 端口占用注意：前端 3300 与「AI Avatar Twin」前端同端口，联调时错开。
