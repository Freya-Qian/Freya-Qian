# 技术适配声明

> 项目：AI 产品工厂｜阶段 1 技术适配｜日期：2026-09-21
> 依据：PRD V1.0（评审优化修订版）+ 通用手册第一至六节

## 1. 产品形态判断
- 产品类型与核心任务：Web 端 AI 产品孵化工作台——一句模糊想法 → 需求澄清 → 竞品证据 → 产品定位 → PRD → MVP 范围 → 研发任务拆解 → 项目资料包导出，达到"可评审/可开发/可交接"状态。
- 核心交互：分阶段确认 + 长文档异步生成（PRD ≤3min 后台任务）；前一阶段产物确认后进入下一阶段，支持手动回退重生成。
- 开发路径：**纵向切片（路径 B）**。理由：PRD、需求摘要、竞品对比、任务拆解都是"必须用眼睛看、亲手编辑确认"才能判断质量的长文档/结构化内容；三栏工作台 + 分阶段确认（PRD 9.2、13 章）本身就是产品核心体验，不能只靠 JSON 和自动化测试验收。
- 当前阶段范围：阶段 2 后端 MVP，拆 4 个子阶段（对齐 PRD 16 章 P0/P1 + s16 固定阶段流水线）：

| 子阶段 | 内容 | 验证重点 |
| --- | --- | --- |
| M1 项目与需求澄清 | 新建项目（含 3 示例想法 + goal_type + 默认竞品）→ 8 问澄清（首轮 1 轮、可跳过；第 2 轮后置）→ 结构化需求摘要（RequirementBrief，可编辑确认） | AI 澄清质量（模糊想法 → 针对性问题 → 结构化摘要） |
| M2 竞品证据与定位 | 用户自选竞品（≤3，贴网址抓取或手动添加）→ 证据卡（source_url 必填 + 置信度）→ 多竞品对比表 → 产品定位与差异点（每个差异点有证据引用） | 证据卡完整性、source_url 必填校验、定位有证据支撑 |
| M3 PRD 生成与任务拆解 | 带证据引用的 PRD 生成/章节编辑/版本 → 证据引用审计 → MVP 范围与版本规划 → 研发任务拆解（DevTask） | PRD 质量、证据引用审计（evidence_id 存在性 + used_in 一致性 + 无证据结论清单）、任务可追溯 |
| M4 资料包导出与迭代记录 | Markdown 导出（P0）+ 飞书复制友好格式（P0）+ GitHub issue 草稿（P1）+ Feedback/DecisionLog 迭代记录 | 导出可独立阅读、含"证据来源与引用说明"、迭代版本可追溯 |

## 2. 采用的默认方案
- 后端：Python + FastAPI + Pydantic + pytest（手册默认栈）。
- 数据库：SQLite + SQLAlchemy（触发条件：User/Project/RequirementBrief/Competitor/CompetitorEvidence/ProductDoc/DevTask/DecisionLog/Feedback/Export 九类实体、多实体关系、版本管理均命中）。
- 文字模型：阿里云百炼 DashScope（OpenAI 兼容，qwen-plus）——国内厂商优先、数据不出境，用户自备 API Key，与「脑洞游戏」「AI Avatar Twin」同平台可复用 Key。
- 前端终端：Web 端 Next.js + TypeScript + Tailwind（阶段 3 正式前端）。
- 阶段 2 验收界面：单个 HTML 挂 FastAPI `static/`（最小验收界面，不提前铺正式前端三栏工作台）。
- 流式：需求澄清/PRD 生成用 SSE；PRD 长文档生成（≤3min）用"提交 + 查询状态"后台任务。

## 3. 触发的按需模块
- SQLite + SQLAlchemy：九类实体、多实体关系、版本管理 → 引入（M1 起；暂缓 Alembic，MVP 用 create_all）。
- 持久化任务记录 + 后台任务（s11）：PRD 生成 ≤3min、资料包导出慢操作 → 引入（M3 起；单进程串行队列，达规模阈值再上任务队列）。
- SSE：需求澄清/PRD 生成流式展示 → 引入（M1 起）。
- 钩子系统（s04）：证据引用审计、生成前后校验/埋点 → 引入（M3 起，用确定性代码实现审计规则，不由模型自主判断）。
- 本地文件目录：导出文件（Markdown/飞书/GitHub 草稿）→ 引入（M4；生产阶段评估对象存储）。
- 竞品名称自动搜索（搜索 API）→ **暂缓 V1**（PRD 7.2 已明确后置）；MVP 竞品证据来自用户贴网址抓取（已实现）+ 手动填写。

## 4. 偏离或暂缓的默认方案
| 默认方案 | 替代/暂缓 | 原因 | 影响 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| 账号体系与多项目云端保存 | MVP 匿名本地用户，User 表预埋 | PRD 8 章决策 | 本地单机，无登录 | V1 上云时 |
| 飞书 / GitHub 真实 API 同步 | 只做复制友好格式 / issue 草稿 | PRD 8 章三通道边界 | 人工粘贴，不接 OAuth | V1 |
| 竞品名称自动搜索 | 暂缓，贴网址抓取 | PRD 7.2 后置 | MVP 已支持贴网址抓取 | V1 |
| Alembic 数据库迁移 | 暂缓，MVP 用 create_all | 单机单用户起步 | 生产前补迁移 | 生产上线前 |
| PostgreSQL | 暂缓，先 SQLite | MVP 本地单机 | 生产评估切换 | 用户量/并发增长时 |
| 正式前端三栏工作台 | 阶段 2 用最小 HTML 验收界面，阶段 3 再上 Next.js | 核心链路未验证不铺正式前端 | 无 | 阶段 3 |

## 5. 强制底线检查
- 密钥与隐私：通过——.env 不入库、不回显；国内厂商优先、项目资料不出境（D7 已定）。
- 数据与任务可恢复：通过——SQLite 持久化 + 后台任务记录，重启可恢复；关键阶段失败可重试、断点续跑（PRD 17.4）。
- 输入输出校验：通过——Pydantic + 模型结构化输出校验 + source_url 必填/格式校验 + 证据引用审计。
- 错误与日志边界：通过——统一 `{"error":{"code","message"}}`，不泄露堆栈，不记密钥/完整用户文档。
- 测试与真实模型验收：mock 自动化测试先行 + 真实模型冒烟；无 Key 时如实写"待验"，不拿 mock 冒充。

## 6. 需要产品经理决定的问题
- 无。决策台账无"待定"项；D2/D3 按既定"待样例打分"流程处理（第一阶段真实冒烟用 5-10 条真实样例定标准）；无新增费用、平台或外部服务（模型用户自备 Key，MVP 本地单机无云费用）。
