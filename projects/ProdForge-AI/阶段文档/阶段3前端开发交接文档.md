## 三、API 速查表（36 个路由，全部就绪）

### 3.1 通用

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/samples` | 冷启动示例想法 + goal_type 枚举 |
| GET | `/health` | 健康检查 |

### 3.2 项目

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| POST | `/projects` | `{name, idea, goal_type}` | ProjectOut（201）|
| GET | `/projects` | — | `[ProjectOut]` |
| GET | `/projects/{id}` | — | ProjectOut |

`goal_type` 枚举：`course`/`portfolio`/`real`/`team_review`。`current_stage` 枚举：`clarify → competitor → position → prd → tasks → package`（固定顺序推进，前一阶段确认后进下一阶段）。

### 3.3 需求澄清

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/projects/{id}/clarify/questions` | 生成 8 问（**异步**，202 → TaskOut）|
| GET | `/projects/{id}/clarify/questions` | 问题列表 `[QuestionOut]` |
| POST | `/projects/{id}/clarify/answers` | 提交答案 `{answers:[{question_id, answer}]}` |
| POST | `/projects/{id}/brief` | 生成需求摘要（**异步**）|
| GET | `/projects/{id}/brief` | 最新摘要 BriefOut |
| PUT | `/projects/{id}/brief` | 编辑 / `{confirm:true}` 确认 → 进 competitor |

必答项：目标用户、场景、成功指标（未答则 brief 接口返回 422）。

### 3.4 异步任务轮询（统一模式）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/tasks/{task_id}` | 轮询任务状态 `queued/processing/success/failed` |

**异步接口统一模式**：POST 返回 202 + `TaskOut`（含 `id`）→ 前端轮询 `GET /tasks/{id}` 直到 `status` 为 `success` 或 `failed` → success 后再 GET 对应资源接口取结果；failed 读 `error` 字段给用户提示。TaskOut 含 `prompt_tokens`/`completion_tokens`/`total_tokens`（成本护栏用，前端可展示）。

### 3.5 竞品与证据

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/projects/{id}/competitors` | 竞品列表 |
| POST | `/projects/{id}/competitors` | 新增竞品（**≤3 个**，超出 409）|
| GET | `/projects/{id}/competitors/{cid}/evidences` | 证据卡列表 |
| POST | `/projects/{id}/competitors/{cid}/evidences` | 手动新增证据卡（source_url 必填）|
| POST | `/projects/{id}/competitors/{cid}/evidences/fetch` | 贴网址抓取（**异步**）|
| PATCH | `/projects/{id}/competitors/{cid}/evidences/{eid}` | 编辑证据卡 |
| DELETE | `/projects/{id}/competitors/{cid}/evidences/{eid}` | 删除（被引用时 409 拦截）|

证据卡关键字段：`ref_key`（引用键 E1/E2…）、`source_type`、`source_url`、`evidence_type`、`confidence`、`used_in`。

### 3.6 产品定位

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/projects/{id}/positioning` | 生成定位（**异步**）|
| GET | `/projects/{id}/positioning` | 最新定位 PositioningOut |
| PUT | `/projects/{id}/positioning` | 编辑 / `{confirm:true}` 确认 → 进 prd |

PositioningOut 关键字段：`one_liner`、`target_users`、`value_proposition`、`differentiators[]`（每项含 `point` + `evidence_refs[]`）、`non_goals`、`comparison[]`（多竞品对比表）、`evidence_refs[]`。

### 3.7 PRD

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/projects/{id}/prd` | 生成 PRD（**异步**，约 30-40s）|
| GET | `/projects/{id}/prd` | 最新 PRD PrdOut |
| PUT | `/projects/{id}/prd` | 编辑章节 / `{confirm:true}` 确认 → 进 tasks |

PrdOut 关键字段：`sections[]`（每章 `{title, content, evidence_refs[], status}`，`status="待确认"` 表示缺证据）、`evidence_refs[]`、`version`。共 11 章。

### 3.8 研发任务拆解

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/projects/{id}/tasks` | 生成任务（**异步**）|
| GET | `/projects/{id}/tasks` | 任务列表（按优先级排序）|
| PATCH | `/projects/{id}/tasks/{tid}` | 编辑单个任务 |
| DELETE | `/projects/{id}/tasks/{tid}` | 删除单个任务 |
| PUT | `/projects/{id}/tasks` | 确认任务 → 进 package（需含 P0 且 ≥5 个，否则 422）|

DevTaskOut 关键字段：`module`（前端/后端/AI/数据/集成/测试）、`title`、`priority`（P0/P1/P2）、`acceptance_criteria`、`dependencies[]`、`source_refs[]`。

### 3.9 迭代记录（R1 已闭环）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/projects/{id}/feedback` | 录入反馈 `{content, affected_sections, author_type}` |
| GET | `/projects/{id}/feedback` | 反馈列表（迭代记录页数据源）|
| GET | `/projects/{id}/decisions` | 决策台账（含系统级 seed + 阶段确认记录）|

`author_type` 枚举：`user`/`teacher`/`system`。

### 3.10 导出

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/projects/{id}/export` | 导出 `{channel}`，返回 `{export_id, channel, title, content}` |

`channel` 枚举：`markdown` / `feishu_copy` / `github_issue`。返回的 `content` 是完整 Markdown 字符串，**前端负责**触发下载/复制（后端不落盘）。

## 四、统一约定

| 项 | 约定 |
|---|---|
| 错误格式 | 统一 `{"error": {"code", "message"}}`，前端按 `code` 分类提示 |
| 常见错误码 | `NOT_READY`(409 阶段未就绪)、`CONFLICT`(409 重复任务/超限)、`INVALID_INPUT`(422)、`NOT_FOUND`(404)、`BUDGET_EXCEEDED`(402 超预算)、`NO_API_KEY`(503) |
| 幂等 | 同类型任务 queued/processing 时重复提交返回 409，前端按钮需 disabled 防重复点击 |
| 竞品上限 | 每项目 ≤3 个竞品 |
| 状态机 | 顺序严格：未确认前一阶段，下一阶段生成接口返回 409 |

## 五、⚠️ 设置页缺口（不阻塞核心闭环，前端开发时需知晓）

PRD 9.1 的「设置」页面要承载两件事，**后端目前均无接口**：

1. **运行时配置 API Key** —— 当前 Key 只从 `.env` 读，无 `/settings` 配置接口。
   - 前端方案 A：设置页只展示「当前是否已配置 Key」+ 提示改 `.env` 后重启；
   - 前端方案 B：后端补 Key 写入接口（涉及密钥落库安全，需产品经理确认）。
2. **数据库导出/导入** —— PRD 8 章 D6「支持导出/导入」，目前只有资料包 Markdown 导出，无 SQLite 备份导出/导入接口。

**建议**：设置页先做静态版（关于 + Key 状态展示 + 改 .env 说明），两项能力作为后续小迭代补后端接口。

## 七、前端开发建议顺序

1. **项目列表 + 新建项目**（含 3 个示例一键填入）→ 打通 `GET/POST /projects`；

3. **竞品证据页**（竞品 CRUD + 证据卡 + 贴网址抓取）；
4. **定位 + PRD 页**（长文档异步生成 + 章节编辑 + 待确认标记展示）；
5. **任务拆解页**（任务列表 + 编辑 + 确认）；
6. **资料包 + 迭代记录页**（导出三通道 + feedback/decisions 列表）；
