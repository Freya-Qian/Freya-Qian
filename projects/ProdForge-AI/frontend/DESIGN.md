# ProdForge AI 界面约定

品牌展示名称统一使用 ProdForge AI；保留现有项目目录与接口命名。最近项目长名称必须在侧栏内省略，不得撑宽网格。需求澄清保留全部回答草稿，摘要默认折叠。阶段表单与提示、导航共用左右边界。

更新：2026-09-23。作用于首页、项目库、阶段工作台、使用指南、设置与弹窗。

需求澄清按必答与选答分组，默认显示必答；当前组全部题目同时展示，不逐题分页。切组保留回答，点击下一步时先提交全部回答，再生成摘要；提交失败时不触发生成，无需单独保存。

## 设计规则

模式为任务操作型工作台。主色 #4d6bfe，强调文字 #3957cc，浅蓝 #edf1ff，白色 #ffffff，侧栏底色 #f7f8fb，边框 #e6e9f0，正文 #222735，辅助文字 #687080。

所有颜色与尺寸从 app/globals.css 的单一规则体系延续；禁止追加另一套主题覆盖层。表单与按钮圆角12px、项目卡18px、弹窗22px、主输入框24px。危险操作使用语义红色，其余操作使用蓝色/中性灰。图标统一 lucide-react。字体使用中文系统无衬线，字距0，标题24–32px、正文12–15px。

左侧导航包括开始新项目、项目、使用指南、设置。项目卡直接呈现真实名称、想法、阶段与更新时间，不用装饰性封面。删除按钮常驻，确认弹窗明确项目名与关联数据范围。运行任务时后端拒绝删除。

## 操作与接口

竞品推荐只是模型建议，不代表已抓取或核验。添加有网址的竞品后自动调用现有 evidences/fetch 异步接口，并展示返回的结论、来源、摘录、启示及可信度。已有竞品提供主动抓取入口，未提供网址时只要求网址；手动证据补充为折叠的可选入口。满额时只显示一处竞品计数，不重复堆叠上限文案和禁用按钮。网站不可访问或内容缺失时保留错误，不虚构完整资料。

每个已有竞品提供删除入口和一次明确确认。DELETE /api/v1/projects/{pid}/competitors/{cid} 删除竞品及证据、释放名额；若被下游引用，前端在同次确认中调用 `detach-references` 保留正文并解除引用，再重试删除，相关下游产物变为需更新。运行任务时拒绝删除；旧数据若多个竞品共用引用键，不自动解除其他竞品的同名引用，应显示具体冲突。测试仅使用隔离数据库，不删除用户已有竞品。

网络记录：本机系统 DNS 会把公网域名映射到 198.18.0.0/15 虚拟地址。抓取器仅在全部解析结果属于该范围时，通过固定公网 IP 的 Cloudflare HTTPS DNS 查询域名（仅发送主机名，不发送页面正文或项目内容），重新校验公网结果并固定 IP 连接，保持 TLS/SNI 与逐跳重定向校验。不得直接放行虚拟地址或关闭内网防护。WebArena、MineDojo 已实测抓取成功。Voyager 推荐地址 voyager.moe 为 NXDOMAIN；官方仓库 https://github.com/MineDojo/Voyager 指向 https://voyager.minedojo.org/，应使用更换抓取链接入口纠正。

前端 http://localhost:3300/ ，后端 http://127.0.0.1:8200/ 。前端经 Next rewrites 调用 /api/v1，不改为访问后端测试页面。

首页提交创建项目；项目详情通过六个阶段标签推进。模型生成均需用户点击，停止等待只停止前端轮询，不代表取消后台任务。使用指南从设置模型到导出共8步，包含真实入口与错误恢复说明。

阶段推进以最新版本为准，而非仅看 `project.current_stage`。需求摘要生成后推进到竞品阶段，在竞品页就地核对并确认，不要求用户跳回第一步；若从其他页面发现摘要过期，提供明确的更新入口。已有竞品和证据应保留。重新生成上游产物后，下游产物应标为需更新，不得把旧的确认状态当作可继续的条件。当前阶段写入 URL，支持刷新及浏览器前进、后退；阶段切换回到新阶段顶部并聚焦主要操作。

工作台的页面与当前项目应反映在 URL 中，支持浏览器返回、前进和刷新。设置表单的未保存输入不能被后台刷新覆盖；创建和删除请求须有限时及状态核对，避免超时后重复提交。定位生成在提交前检查是否有可用竞品证据；研发任务确认须对应最新已确认 PRD。项目资料包若允许提前导出，应明确是阶段性内容，不得暗示流程已经完成。

项目删除 DELETE /api/v1/projects/{id}，有queued/processing任务返回409；404适用于不存在或不属于当前本地用户的项目。成功删除全部关联资料。密钥不在日志、文档或页面回显。
